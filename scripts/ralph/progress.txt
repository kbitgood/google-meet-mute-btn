## Codebase Patterns
(Patterns discovered during this feature build)
- macOS Quick Actions are stored as .workflow bundles in ~/Library/Services/
- Workflow bundles require Info.plist (service metadata) and document.wflow (Automator actions)
- Both plist files must be valid XML, verified with `plutil -lint`
- Arc's `execute javascript` can hang indefinitely - always use `with timeout` wrapper
- Google Meet URLs: only process actual meetings (xxx-xxxx-xxx), not landing/home pages

### Edge Cases Discovered and Fixed:
1. **Landing page timeout issue**: The original script matched ALL meet.google.com URLs including
   landing pages, homepage, and other non-meeting pages. JavaScript execution on these pages would
   hang indefinitely because there's no mute button to query.
   
   **Fix**: Updated URL matching to filter out non-meeting pages:
   - meet.google.com/landing
   - meet.google.com/ (homepage)
   - meet.google.com/?authuser=N
   - meet.google.com/new
   - meet.google.com/lookup
   
   Now only actual meeting room URLs (meet.google.com/xxx-xxxx-xxx) are processed.

2. **JavaScript execution timeout**: Arc's `execute javascript` command can hang if a tab is
   unresponsive or in a specific state.
   
   **Fix**: Added `with timeout of 3 seconds` wrapper around all JavaScript execution calls.
   If timeout occurs, the tab is skipped and processing continues.

3. **Updated notification message**: Changed "No Google Meet tabs found" to "No active Google 
   Meet calls found" to be more accurate about what the script is looking for.
